# Seed Oracle / 种子先知

Seed Oracle 是《Slay the Spire 2》`0.113.0` 的路线信息前瞻 Mod。它在地图节点 HoverTip 中显示当前跑局已经能够确定的信息，并为每一项结果标注“确定”“当前世界线”“路线相关”或“暂不支持”。

当前版本实现：

- 普通战、精英战与 Boss 的 Encounter 队列前瞻；
- 枚举从当前位置到目标节点的可行路线，并统一用“绿色线路”“青色线路”等完整彩色线路对应不同结果；
- 每个颜色标签注明该结果包含的完整路线数；只有从当前位置连续沿同色线路走到目标才对应该结果，共线色带表示在分岔前仍有多种结果可能；
- 多种结果共用同一段地图边时，将颜色排成独立的不透明平行色带，避免后绘制路线覆盖前一条或因透明叠加而混色；
- 路线会保留到查看另一个节点或关闭地图，并按节点实际图标中心连接；路线覆盖层位于 HoverTip 下方，不再遮住文字；
- 修复中途推进后彩色路线落到地图背景层下方的问题；路线、顶部总览和 HoverTip 使用独立的显示层级；
- 地图顶部中央提供“先古 / Boss”按钮，按需展开或隐藏三幕总览；先古初始选项在序列化影子跑局中用事件独立 RNG 生成，已访问选项取自历史记录，未来幕中依赖牌组、遗物或进度的结果标成“按当前状态预测”；
- 对特兹卡塔拉、诺努佩佩、坦克斯与帕尔的动态候选池，用同一事件 RNG 分别计算条件成立和不成立的结果；只有实际选项发生变化时才显示“若条件成立：A 替换 B”，并注明其余条件保持不变；
- 相同预测结果与等效选择合并显示；长提示按原生字体的实际尺寸分页，Shift+滚轮翻页时锁定地图滚动，整组面板保持在屏幕安全区内；
- Boss 前瞻把共同的遭遇与怪物信息只显示一次，并把不同路线掉落压缩到最多三块面板，同时保留每条彩色完整路线及其终点连线；
- 支持普通连线、羽翼之靴剩余次数和 Flight 修正下的路线可达性；
- 沿每条路线依次推进问号房间、Event、普通战、精英战和 Boss 队列，显示目标事件或战斗及怪物阵容；
- 使用 Encounter 的独立确定性种子生成怪物阵容；
- 对下一步可进入且遭遇唯一的战斗，用克隆的 `Niche` RNG 精确生成怪物初始 HP；隔着其他房间的战斗在普通悬窗中保留“未确定”，战前 worker 可计算条件场景；
- 用克隆的 `UnknownMapPoint` RNG、赔率状态和 Hook 监听器预测路线上的连续 `?` 房间类型；
- 用克隆的 Event 队列和 Hook 监听器预测路线上的事件身份；
- 对 Random Foreseer 已支持的 31 类事件，在序列化影子跑局中初始化事件选项，并分别显示入场时原生选项已经生成的卡牌、遗物、药水与选择后的额外预测；滑脚木桥的首次无伤删牌、旺戈商店的精选遗物等不会因 Random Foreseer 只补充后续结果而遗漏；远端事件会先推进沿途已建模的奖励状态；
- 使用原版商店生成器按路线生成初始库存，包括卡牌、遗物、药水、半价、价格和删牌价；按已建模的沿途基础奖励推进共享 RNG 与遗物袋，未执行的拾取、事件、购买和补货仍标为条件；
- 按可行路线推进克隆的 `Rewards`、`Shops`、卡牌/药水赔率和玩家遗物袋，显示战后金币、卡牌、药水与遗物；支持当前游戏内会改写基础奖励的遗物与自定义模式；
- 使用克隆的 `TreasureRoomRelics` RNG 与共享遗物袋预测宝箱遗物和金币，处理银坩埚空箱与首次教学宝箱；白银熔炉按游戏规则只在打开的第一个宝箱生效（进房计数器先递增再判定出货），沿途后续宝箱正常预测遗物与金币；
- 使用游戏支持的 `[gold]`、`[green]`、`[orange]` 和 `[blue]` 富文本标签显示预测状态与价格；
- 卡牌、遗物与药水名称按实际稀有度显示为普通白、罕见蓝、稀有金等颜色；Mod 设置页可改用原生卡图缩略图代替卡名，彩色菱形继续标出稀有度，升级牌保留“+”；
- Mod 设置页可关闭非计划模式下的路线、标记和地图预测浮窗（默认开启）；打开计划面板仍显示规划信息，面板顶部固定提示“当前计划模式，点击房间不会进入，需要进入时请关闭计划面板”；
- 地图顶部提供“战损与模拟”按钮和可见面板；打开面板与地图悬停都不会启动 worker。每个场景有独立“计算”按钮，未选择的路线不排队；相同跑局状态与搜索设置会直接恢复缓存结果；
- 面板用与地图路线标记一致的彩色三角形、正方形、菱形等图形区分路线，悬停一行会在地图上高亮对应目标与路径；可选择单场搜索预算与并行度，并查看耗时、可信度和药水计划；
- 面板实时显示隔离 Combat Solver worker 的 PID、工作集、私有内存和静音状态；可选择保活 2、10、30 分钟、一直维持或任务结束后自动关闭，也可手动关闭及重启/预热；
- Combat Solver 在主游戏初始化时钉住本次会话实际载入的 Mod 文件；Steam 运行中更新工坊目录时，隔离 worker 仍以主进程版本为准，不会因磁盘版本先行更新而误报 Mod 集合不一致；
- “咱俩碰一碰”页可手动运行 0～10 个假设样本，对象包括当前幕随机弱怪池、强怪池、精英池、指定普通/精英怪组和当前 Boss；指定怪组及样本结果使用游戏当前语言的本地化遭遇名称，逐样本显示战损、终局生命、回合和用药，并汇总最低、平均与最高战损；
- 纯模拟明确使用假定的怪物组与怪物生命、开局洗牌、怪物行动和其他战斗随机数，只用当前牌组、遗物、药水与生命比较威胁，不把远处未确定战斗显示成预测事实；
- 规划中的普通战、精英战、Boss、问号点战斗和事件选项战斗可从规划快照运行模拟，默认 3 次、可选 1～10 次；成功结果可作为该节点的生命与用药参照写回规划；
- 手动计算覆盖每条当前可行路线上的第一场确定战斗。目标前允许经过不会直接消耗战斗序列的篝火、宝箱或商店，目标坐标和中间楼层历史会传入隔离进程；未决事件和中间战斗不跳过计算；
- 若目标前有篝火，面板同时给出“沿途状态保持当前值”和“在前置篝火休息后入战”场景。休息分支在开战 Hook 前应用游戏当前规则算出的 HP，并明确标出尚未模拟的奖励、锻造与其他触发；
- 探测 Random Foreseer 与 Combat Solver 的版本和可调用能力；
- Debug 构建在每次地图预测前后比较 live state 指纹。

远端路线预测只展开实际算出内容变化的选择分支：以一条具体选择链为参照，逐格列出其他选择造成的商品、价格或掉落变化。相同结果合并，未算出具体结果的情况不再追加泛泛提示。计算仍有预算和机制覆盖范围，分支列表不代表穷尽全部玩法。

当前版本同时兼容 Combat Solver public API v5；检测到 API v6 时额外启用规划快照战斗模拟。v6 扩展通过独立 `SerializableRun` 把规划中的牌组、生命、药水、地图和事件状态交给 worker，支持问号点与事件战斗；旧的 v5 工坊版仍可使用确定路线和当前状态假设样本，规划模拟控件会明确标记为不可用。所有战斗都在独立 headless 游戏进程中初始化和求解，主进程调用前后核对完整跑局/RNG 状态令牌。远端确定路线数值仍是清楚标注的条件结果：沿途若拿牌、拿遗物、用药、购买、锻造或触发其他状态变化，应在实际选择后重新计算。
设计评估与验证边界见 [docs/combat-solver-precombat-assessment.md](docs/combat-solver-precombat-assessment.md)。

## 0.1.59 极速商店「全景与规划」窗口：回答整个六选三

- 0.1.58 的浮窗只回答“悬浮的这一件 + 单件先行”。但极速商店是**六选三**，“多加 2 次选择”还会把预算扩到 5 件，每次成功购买都推动随机数流，完整的可能性空间是一大堆“先买了哪几件”的组合。本版在店内新增自建窗口一次摆全，原生浮窗保持不变。
- **机制先说清**（文档：[docs/validation/blitz-shop-multi-purchase-2026-11-14.md](docs/validation/blitz-shop-multi-purchase-2026-11-14.md)）：每件货物的消耗量只由条目类型决定（卡牌奖励 +18、附魔卡牌奖励 +12、稀有/棱镜/无色 +9、升级稀有卡奖励 +10、药水 +4、遗物 +1 且动遗物袋、诅咒条目各藏一张诅咒、变化走 Transformations、升级/删牌/附魔完全不动流）；于是**某件货物的内容只取决于“在它之前已完成购买的货物集合”，与那几件的先后顺序无关**——遗物袋按袋尾扣减、诅咒在自身位置掷，同集合换顺序读到的流位置相同。唯一例外是“自动升级”：它洗整副牌库，前序奖励实际领牌会改变牌库顺序，窗口明确标注。
- **全景页**：每件货物一行组——「直接买」结果，加上**按相同结果合并**的“先买 ②药水＋④遗物 后：……”变化行；全都不变时写“先买哪几件都不会改变这一项”；变化太多时折叠成计数并指向求购页。无法完成的前缀组合（如自动升级没有可选牌）如实写“无法推算”。
- **求购页（默认页，需求导向，照搬水晶球预测器的展示规则）**：不再出现“三选一：A / B / C”这类句子——每件货物一个格子，格子里是**它在此店任何买法下可能给出的具体物品**：奖励三选一里的每一张牌、每瓶药水、每件遗物、诅咒，都是**可点击的小标签**（稀有度着色，与卡牌文本同色表）；**悬浮显示物品自己的信息卡**（卡牌：费用圆徽＋名称＋类型＋`GetDescriptionForPile` 完整描述，升级牌走升级预览；药水/遗物：标题＋`DynamicDescription`），卡片描述用游戏原生 `MegaRichTextLabel` 渲染、贴近鼠标并夹在视口内——与水晶球的悬浮卡同构。**悬浮卡的富文本必须带主题字体覆盖**（`GetThemeFont`＋`AddThemeFontOverride`，`AutoSizeEnabled=false` 公开属性）：游戏的 mega_text 层在 `_Ready` 里断言无字体覆盖即抛异常，首个版本漏了它，鼠标碰到物品标签就反复抛错直至进程闪退；自检现在把面板挂进场景树实测悬浮并断言覆盖存在。点击物品即为“愿望”（★ 标记），可对多件货物各许一个；底部水晶球式计划区：**「计划：N 次点击」**＋路线“② → ③ → ①”＋每步的物品标签行（愿望达成 ✓、垫位标注）＋剩余可带走；无解给原因（先后冲突 / 次数不够 / 已被带走）。愿望按“物品身份（类型+名称+升级）”匹配：解算器找出所有能交出该物品的前缀组合再求顺序（纯查表、垫位最少优先）；真实购买后自动在重算的货架上按物品重新匹配。需要选牌的货物（升级/删牌/变化/附魔）没有固定物品，格子注明“内容随你的选择变化”。窗口默认打开在求购页，全景页退为第二个页签；布局完成后窗口会把自己夹回可视视口内。
- 计算在后台任务上跑（最坏 6 件 × 31 个前缀组合 ≈ 186 次影子购买，与悬浮同一探针、零重写抽取），按“剩余次数+货物状态”指纹缓存，真实购买一件后自动整架重算；买过的货物在两页都标“（已带走）”。
- 建模边界沿用既有原则：前序购买按“已购买、奖励界面未领取”处理（只有读牌库的自动升级受实际领奖影响，已标注）；需要选牌的前序货物按“自动选第一张候选”补全——选哪张不动随机数，只影响你自己的结果，窗口脚注写明。
- 设置页新增“极速商店：全景与规划窗口”开关（默认开）。自检新增 `blitz-plan`（覆盖=在场货物、预算约束、与悬浮逐字一致、整架耗时、逐帧分步与整批枚举逐字一致）、`blitz-plan-order`（同一前缀集合正反两种顺序买下来，第三件结果逐字相同——顺序无关性是实测不是假设）、`blitz-plan-seq`（顺序查表 vs 独立克隆逐步真买逐字对齐、超预算拒绝）、`blitz-plan-wish`（合成表上求购解算器：可解含垫位、互斥愿望报冲突、超次数报预算不足）、`blitz-plan-dedupe`（同签名组合一致且与真买对齐、确实少买）、`blitz-plan-panel`（两个补丁确实挂在商店开合上、两页渲染非空、求购点选后出点选顺序）。
- **首发的两处修复**：一是线程——购买命令会顺手把卡牌预览、附魔特效等节点加进 `GlobalUi` 的容器（`CardPileCmd`/`CreatureCmd`/`NCardEnchantVfx`），这些只能在主线程碰；最初把枚举放进 `Task.Run` 后台线程，枚举到这类条目就跨线程改 UI 树导致整个游戏卡死（收起窗口并不会停掉后台枚举，“收起后卡住”与卡死是同一件事）。二是可找回性——“收起”不再隐藏整个窗口（早期版本还依赖一个放在商店场景里的外部按钮，位置假设不成立，收起后就什么都不剩了），改为**折叠成标题条留在原地**：标题、页签和“展开”按钮始终可见，商店开着窗口就一定在；折叠状态跨商店记住，展开时若还没算过会自动补算。
- **变化预测扩展到奖励牌与诅咒（按顺序拿牌/收诅咒再送去变化）**：前序回放统一改为“直接生成该货物”——除了推进流，还顺带收割它开出的奖励屏候选与送出的诅咒。于是“变化”的表不只回答牌库里已有的牌，也回答**本次购物从前序卡牌奖励里拿到的牌**和**前序诅咒货物送进牌库的诅咒**：每个奖励屏上的每张牌、每张进库的诅咒都是候选（游戏规则：诅咒无 Eternal 关键字即可变化，且诅咒源从整个诅咒池抽——买诅咒货物把“愧疚”洗成“铃铛的诅咒”是真实结果）；变化结果仍在同一 `Transformations` 位置对各候选各抽一次（排除自身）；前序里有已完成的“变化”时，后续变化读的位置顺次 +1。**求购页的变化格子列出“变化结果与路径”**：每个结果一行，右列全部来源——“X（牌库）／Y（③奖励牌）／Z（⑥诅咒）”，即依照哪种或哪些方式可获得该结果；结果 chip 可直接许愿，解算器给出购买顺序。修掉一个真 bug：诅咒是池子原型卡，游戏在 `Owner` 读取上就 `AssertMutable` 抛异常，之前被逐候选 try/catch 静默吞掉（这正是“诅咒变化结果没列出”的原因）——现在用 `IsMutable` 判别并按 `AddCursesToDeck` 的方式物化为带主实例。自检 `blitz-plan-rewardtransform`：合成“卡牌奖励＋变化＋多加2次”货架，断言奖励候选与奖励行自开屏逐张一致、诅咒候选带路径标签出现且结果为真实变化。
- **生成引擎（0.1.59 定稿：随机数定位直生，不再影子真买）**：每类条目对 `Shops`/`Rewards` 的推进量由生成器自测（开架时每类在偏移 0 跑一次、读克隆计数器差），某件货物在“先买了哪几件”后的内容 = **克隆随机数流、跳过Σ推进量次抽取、在该位置调用游戏原生工厂**（`CardReward.Populate`、`PotionFactory`、`RollRarity`+遗物袋重放、`StableShuffle`、诅咒池 `NextItem`），遗物袋与牌库按前缀重放（袋 `LoadFromSerializable` 原位重置、诅咒按序进库）。**全程零购买执行**——影子图只作牌池/Hook 的只读上下文，卡牌预览、特效节点、同步器事件无路可出，早期版本数百次克隆购买导致进店闪退的路径彻底移除。悬浮预测（单件、每周一次）仍走 0.1.54 的购买探针并作为 parity 基准：自检断言每件货物直接行与一个非空前缀行的直生结果与真买逐字一致。性能：整架 96 行约 24–40ms 且与存档大小无关（旧方案每行一次全量反序列化，真实跑局进店卡数秒）；每店仅一次 `CreateState` 建只读上下文（等同一次悬浮的成本）。前缀签名去重、购买后防抖重算、指纹缓存维持不变；规划/求购查表遇到缺失组合行明确拒绝。

## 0.1.58 极速商店浮窗回答“顺序会怎么改变这一件”

- 实测机制（`blitz-stream` 逐条目量了购买前后每条流的计数器）：**每一次成功购买都至少把 `Shops` 推 +1**，各条目消耗差异很大——卡牌奖励 +18、稀有卡牌奖励/棱镜/无色 +9、附魔卡牌奖励 +12、升级稀有卡牌奖励 +10、药水 +4、遗物/+2 次/满血 +1；`TwoRelics` 还动共享遗物袋，`CardRewardOfEachRarity` 另走 `Rewards` +9。两个“看起来固定”的条目其实都会先 `GiveCurse()` 掷一张诅咒（`TwoMoreChoices` 和满血+最大生命），所以它们的结果也随顺序变。
- 店内悬浮现在对**悬浮的这一件**逐个枚举“其余可用货物先买会怎样”：在同一克隆上真的先买另一件、再买这一件，把**结果真的不同**的按先行件分组列出：
  ```
  → 药水：无色药水、能力药水
  → 先买 稀有卡牌奖励 后：药水：能力药水、超巨化药水
  → 先买 遗物 后：药水：赌徒特酿、敏捷药水
  ```
  所有先行件都不改变时写 `→ 先买哪一件都不会改变这一项`（比如升级/删牌这类结果在你自己选牌上的）。需要选牌的先行件跳过——它没完成购买、流没动，无从断言。
- 买完一件后浮窗整体重算（0.1.55 的缓存规则不变），所以逐步悬浮能跟着你的选择走到底；本版只是把“第一步之后”也摆在了眼前。整架 6 件的完整预测共 45 ms。
- 自检新增 `blitz-stream`（20 类条目 × 各流计数器差分）与 `blitz-order`（卡牌奖励/满血/+2 次先行都会改变药水；满血与 +2 次选择件自身的诅咒随先行件变）；`blitz-hover-ms` 断言整架预测耗时。
- 地图浮窗仍按“这一项先买”推算并保留脚注；店内浮窗是当下状态的完整版。

## 0.1.57 极速商店的「卡牌变化服务」列出每张牌变成什么

- 极速商店的变化货之前和升级/删牌/附魔一样，只写「需要你选一张牌（14 张可选）」。但变化是这几类里**唯一有随机结果**的，而且结果能算：原生是 `CardCmd.TransformToRandom(card, PlayerRng.Transformations)`，一次抽取，选项是「本角色卡池、稀有度 2–4、排掉这张牌自己」。
- 所以按原生同一个工厂函数逐张算：每个候选都用 `Transformations` 的**同一位置**克隆一次，调 `CardFactory.CreateRandomCardForTransform`。结果不是「每张牌各变各的」——同一池子的牌几乎都落到同一张（只差排除自身造成的错位），所以直接写「12 张可选牌都变化为 子弹时间」；真出现分歧才按结果分组写「A、B 等 5 张牌变化为 X」。
- 只对变化这么做：升级就是原牌 +、删牌没有产物、附魔固定，列出来全是噪声，仍保留原提示。
- 自检 `blitz-transform`：候选数 = 可选项数、结果不等于来源、不会每张都重新抽（`results=1` 即证明用的是同一位置），以及**真买一次**做 A/B——第一个和最后一个候选各买一次，落地牌必须与表里写的一字不差。

## 0.1.56 店内浮窗换成按槽位绑定，并验到补丁真的挂上了

- 0.1.55 的店内预测靠 `RunManager.MerchantSynchronizer.GetInventoryFor(player)` 反查“这件货属于哪个库存”。这条路自检里是通的（影子作用域下返回影子库存），但它依赖运行时按玩家槽位索引一张列表，一旦列表为空或索引错位就整段静默失败。
- 现在主路径改成**槽位绑定**：`NBlitzMerchantSlot.FillSlot` 执行时，从槽位节点向上找到 `NMerchantInventory` 面板，把它手里的 `Inventory` 直接记到这条货物上。这正是把货物摆上屏幕的那份库存，不再经过任何全局查找；原查询降为兜底。
- 走到兜底或任何一环不成立时，日志写一行 `[BlitzHover] no prediction for <条目>: <原因>`（每种条目每类原因只写一次），下次真出问题可以直接从日志读出卡在哪一步，不用再猜。
- 自检补上两件以前其实没测的事：用 `Harmony.GetPatchInfo` 断言两个补丁（`HoverTips` postfix、`FillSlot` postfix）**确实挂在游戏方法上**——以前只直接调 `Describe`，补丁没挂上也会绿；以及影子条目悬浮时返回的原生浮窗与原生描述**逐字相同**，确认护栏不会把游戏自带的提示改坏。

## 0.1.55 预测挪进商店里的货物浮窗

- 0.1.54 的逐项收益只出现在**地图商店节点**的浮窗里；人站在店里悬浮货物图标时，看到的还是原生那三行。现在预测直接并进原生浮窗：标题保持原样，原生描述下面接 `→` 行。
- 站在店里时探针从**当前存档状态**出发，所以就是“现在买它会怎样”：买过一件之后，剩下的货物会按已经移动过的随机数流重算，不会给出过期数字。
- 探针不再重建货架，改为**复制条目**（浅拷贝后把 `_player` 换成克隆玩家、清掉指向真实库存的事件订阅）。必须复制而不是重新生成：`CardEnchant` 与 `PrismaticCardReward` 的构造器自己也会掷一次（附魔、角色），重新生成会挑到别的内容，还会把后面的流推走。
- 缓存按“可带走次数”失效：买到第 2 件时，剩余货物的预测整体重算；同一件反复悬浮只算一次，约 7 ms。
- 地图浮窗与店内浮窗共用一份文案（`BlitzYieldText`），两边不会给出不同说法；地图那边保留“按这一项先买推算”的脚注，店里则不需要（本来就是当下）。
- 自检新增：店内悬浮 6 项全部有预测、同一件连问两次答案一致、合并后仍是**一个**浮窗且保留原生标题与原描述。

## 0.1.54 极速商店逐项预测到手内容

- 极速商店卖的是动作，内容在买下那一刻才掷（`PlayerRng.Shops`）。浮窗现在在每项下面直接写“买这一项会给你什么”：卡牌奖励列出三张候选、遗物与药水点名、诅咒点名、自动升级的牌点名、“多加 2 次选择”写明。
- 做法是**在影子克隆上真的买一次**：从“货架生成之前”的快照恢复，重建同一份货架（条目类型与标题都对得上才认），走同一条购买入口，用奖励回放拦下 `RewardsSet`，调 `GenerateWithoutOffering()` 让原生代码把牌/遗物/药水掷出来，只记录不领取。没有重写任何抽取规则，权重、`Blitz` 稀有度档、遗物袋回退、诅咒池全部与原生一致。
- 需要你选牌的四类（升级、变化、删牌、附魔/Glam）克隆替不了你的选择：探针停在选择界面，写“需要你选一张牌（N 张可选），结果随选择改变”，不会替你选。
- 所有收益都按“这一项就是下一件买的”推算——每项在买下时消耗同一串 `Shops` 随机数，先买别的会把后面结果推走。浮窗末尾一行写明这个前提。
- 顺带修掉一个真实漏洞：`BlitzMerchantTwoMoreChoicesEntry` 通过 `MerchantSynchronizer.GetInventoryFor` 改“可带走次数”，影子玩家会被它按槽位索引到**真实**库存。该查询现在在影子作用域内返回影子库存。
- 自检新增 `blitz-yield`：6 项全部可预测、每组卡牌奖励恰好 3 张、需要选牌的项与可选项数自洽、浮窗含收益行；报告同时打印渲染后的每一行与耗时。

## 0.1.51 同一份结果不再按路线分页

- 宝箱房此前会把同一个宝箱拆成多页：九条路线进同一个宝箱、遗物与金币完全一样，却因为“怎么走到这里”不同而算成九个结果。分线色带用 `ReferenceCondition`/`ReferenceChoicePaths`/`ChoiceBranches` 参与分组，等于把条件当成了答案。
- 现在宝箱分组只看内容（遗物、金币、是否空箱）：前置怎么走都不改变宝箱时，只出一页；`条件（N 种前期选法结果相同）` 一行说明其余选法同结果。会改变内容的条件分支（如某选项让宝箱换成另一件遗物）仍然算不同结果，继续分开。
- 实测（真实存档自检）：同一宝箱 22 条路线、2 种线路标签 → 7 页，与 7 种真实内容一一对应；分组数不再随路线数增长。
- 战后掉落同样处理：分组只看金币、卡牌、药水、遗物、重掷/狩猎分支与条件分支结果，不再看沿途条件。内容真的不同时仍然分开、仍然各自上色。
- 有意保留商店的逐路线分组：库存面板自己合并同价库存，且商店浮窗需要逐线路预测才能显示；商店的差异来自库存与事件选项，不是“路线标签”。
- 自检补了“一个宝箱九条路 = 一组一页、页面不出现线路名”的回归断言；规划战斗模拟的冷启动采样上限从 30 秒放宽到 120 秒（首次采样包含启动独立游戏进程的开销，30 秒会在 worker 还没开始监听时判超时，半启动的进程随后又和下一个采样争用设置文件）。

## 0.1.49 奖励窗口不再汇报沿途状态

## 0.1.48 只区分真正的成因

- 路线标签不再被当作“结果不同的原因”。商店面板改按真正改变随机数的选择来分组：同一份库存若只由脑蛭事件的选项决定，两条顺序不同的路线不再各占一块，而是合并成「脑蛭：分享知识」与「脑蛭：把它扯下来」。
- 事件选项按“事件身份 + 选项”对齐列（`CauseKey`/`CauseLabel`），因此“先小怪后脑蛭”和“先脑蛭后小怪”即使事件楼层不同也会并成同一个条件；显示用事件名而不是楼层。
- 只有当一组除了路线之外没有别的解释时，才保留线路色标（例如某份库存确实只有绿色线能到）。
- 同一个“任意选择”前提在每个分组里重复出现时只打印一次；具体选项不会被扩散到未曾枚举它的分组。
- 反例保护：同一个条件在两条不相交线路上给出不同库存时，路线本身就是成因，此时不隐藏路线标签。
- 回归新增 CAUSE 场景：两条线路 × 两个选项 × 不同事件楼层，输出必须是「基础库存：脑蛭：分享知识」加「脑蛭：把它扯下来（相对基础）：」，且不含线路名与楼层。

## 0.1.47 商店浮窗只留结论

- 商店库存稀有度、升级、价格与补货全部来自 `Shops` 流，前期选牌、事件选牌、涅奥遗物、去哪条路线都无法改变它。因此当所有上游选法收敛到同一份库存时，浮窗只写一行「基础库存（N 种前期选法结果相同）：」加库存本身。
- 路线标签不再豁免压缩：`青色线路：2、3层选牌：任意选择` 这类既没写清结果、又没给出可操作信息的行一并消失。
- 压缩生效时同时省略「前提 / 路线 / 任意选择」这些选择类前提，只保留仍然影响结果的部分（商店金币不足、药水栏已满、补货未计算等）。
- 战斗奖励、宝箱与分组比较共用同一规则；只有存在两种以上不同结果时才继续列出条件分支。
- 回归新增 ROUTED 场景：5 个涅奥起点 × 青/绿两条线路 × 拿/不拿奖励选牌共 10 种组合落在同一份库存时，输出必须只剩「基础库存（10 种前期选法结果相同）：」，不得出现线路名、`前提`、`或` 与具体选牌格。

## 0.1.46 求解器超时直接给满

- 每次战斗评估一律使用 Combat Solver 允许的最大墙钟上限 180 秒，不再按预算推一个固定值，也不再从历史耗时逐级抬升。超时会丢弃整次计算结果并作废 worker 会话，所以等待远比误杀便宜。
- 搜索深度仍由搜索预算决定：上限只回答「最多等多久」，不改变求解器找到的路线。
- 超时提示相应简化成「超时：180 秒上限内没有结果。」，不再承诺更长的重试；重试按钮恢复为「重试」。
- `OverallTimeoutMilliseconds` 仍写进结果与日志（`[CombatSolver] timeout encounter=… ceiling=180000 elapsed=…`），便于定位真正卡死的请求。

## 0.1.45 预测显示与求解器反馈

- 单库存/单结果的分支不再逐条罗列前期选择：同一个结果的多种上游选法收敛为一行「（N 种前期选法结果相同）」。此前的商店浮窗会把涅奥遗物、前几层选牌、事件选牌的全部组合拼成十余行，占满浮窗却没有任何可操作信息。
- 战斗奖励、宝箱与路线分组共用同一套压缩规则；带线路标签的比较浮窗不压缩，避免把「哪条路给这份库存」一起吃掉。
- 战斗模拟增加过程反馈：手动计算的行内状态、批量模拟摘要、规划面板单次模拟都会显示「已用 / 上限 秒 · 启动求解进程 / 载入跑局快照 / 搜索出牌路线 · 内存」。
- 超时结果单独提示，不再与普通失败混在一起；求解器缓存键不再包含墙钟上限（上限只决定等多久，结果由搜索预算决定）。

## 0.1.40 地图预测性能

## 0.1.39 预测锻造误播牌组动画

预测锻造明确关闭动画，副本按对象身份持续隔离，覆盖嵌套分支和隔离结束后的回调；真实玩家归属与会员卡价格计算保持各自原有行为。[复现与修复记录](docs/validation/shadow-animation-2026-10-17.md)。

## 0.1.38 商店购买机制与补货

普通购买沿用进店时已经生成的商品，不额外消耗随机数；送货员补货、星系仪生成五组选牌以及遗物改变奖励规则会产生实际后续分支。购买预测改为执行原版购买、获得效果、补货、购买后回调及库存更新，补齐此前手动扣钱和加物品遗漏的步骤。星盘变牌使用独立的 Niche 随机流，不能一概当成奖励随机数变化。

路线规划保留同一次进店的库存，按购买顺序更新会员卡折扣与补货，并可再次购买送货员补出的同一格商品。需要额外指定变牌等目标的购买会保留未完成条件；不会自动代选后宣称确定。逐项随机流对照及原生购买实测见 [商店机制核查](docs/validation/merchant-mechanisms-2026-10-17.md)。

## 0.1.37 商店后续掉落与缺项原因

前置商店不再把同结果的“不买／购买各张卡”逐一列出。对已核对的商店后直接进入普通战斗场景，普通购牌不会改变奖励时显示“14层购牌：任意选择（137金内）”，覆盖预算内的多张连买。其他后续流程只合并实际验证的单件购买，不扩大为任意组合。

保留实际商品、价格和预算，并区分“买不起”“药水栏满”和“未计算购买”。例如飞溅166金、预计137金时明确说明买不起；若转经轮可购买并改变后方掉落，则列出具体增加的选牌。原因及52种购牌组合对照见 [商店购买摘要验证](docs/validation/shop-purchase-summary-2026-10-17.md)。

## 0.1.36 明确显示任意选择

已验证等效的普通奖励不再只隐藏默认跳过操作，统一显示“2、3层选牌：任意选择”，同一范围只说明一次，不标成必要前提。浮木存在时把普通拿牌／跳过与重掷分开，显示“任意选择（不重掷）”；转经轮、白星产生的多组普通选牌同样保留各组的等效范围。

等效检查只读取实际使用的卡池、遗物袋和回调，未参与预测的注册模型不再阻止判断；尚未证实等效的部分选项和真正影响后续结果的行为继续保留条件。[验证记录](docs/validation/any-card-choice-2026-10-15.md)。

## 0.1.35 普通拿牌与跳过的无关条件

原版在生成战斗奖励时就抽好候选牌，普通拿牌或跳过不再抽随机数。对已核对的普通战斗、脑蛭、目标商店流程，若拿牌只改变牌组且后续操作不读取这些变化，省略“2、3层跳过选牌”等默认操作前提。遇到重掷、狩猎、拿牌触发效果或读取现有牌组的事件时保留相应条件；条件消除不依赖分支枚举碰巧是否完成。

两场战斗的全部16种普通拿牌／跳过组合，分别对照脑蛭5种“分享知识”选牌和3种“把它扯下来”选牌，共128例商店内容及价格一致。原版核查、反例与性能记录见 [普通选牌条件核查](docs/validation/ordinary-card-choice-2026-10-15.md)。

## 0.1.34 奖励条件与商店可读性

战斗奖励、Boss奖励和宝箱接入结构化选择条件，补齐参照结果的菜单范围；已验证全部选法等效时不显示旧的逐项枚举。只对某条线路成立的前提在该线路旁说明一次。

商店基础库存增加①②③等格位编号。每种其他情况用一个标题列出完整变化，按商品类别合成行，例如“角色卡：②完美打击48金（-24）、③破灭48金（-24）”。基础库存已列出的旧商品和旧价格不再重复。实测及完整节点浮窗验证见 [奖励条件与商店可读性](docs/validation/readable-forecast-2026-10-15.md)。

## 0.1.33 选择条件与共有变化

商店条件按实际选项范围合并。一个步骤的全部选法都得到相同结果时，删除该步骤；同一事件选项下的不同选牌目标得到相同结果时，只写事件选项。只算出部分选法时仍列出具体子集，保持先后顺序和选择之间的关联。

所有结果共同依赖的前提只写一次，例如“2、3层跳过选牌”。多个分支共有的商品格位变化也只列一次，并注明适用条件；各分支剩余差异单列。实测与边界见 [条件简并验证](docs/validation/condition-summary-2026-10-15.md)。

## 0.1.32 提示布局与商店摘要

取消按约10个汉字强制换行，改由原生字体按实际宽度排版；浮窗常规宽度520像素，并按视口高度分页，保留所有已算内容。按住 **Shift** 时锁定地图滚轮、拖动和滚动惯性，Shift+滚轮只翻提示页，松开后恢复地图滚动。

商店按完整商品、格位、升级/附魔、价格、半价状态与删牌价格合并相同库存。覆盖已计算路线与选择组合最多的一份库存作为基础，先展示一次完整清单，再列对应条件；其他情况只展示相对基础的变化格位及价格增减。覆盖数量不代表发生概率。

原生布局、商店合并和地图滚轮验证见 [布局与商店摘要验证](docs/validation/layout-shop-scroll-2026-10-14.md)。

## 0.1.31 悬停性能与完整提示

复杂路线的完整悬停预测增加同跑局状态缓存和分阶段计算预算。已知房间线路直接推进队列位置，相同基础奖励/商品序列只生成一次；事件与问号仍走独立跑局。卡牌、遗物、药水、RNG、地图、当前事件页或语言变化会使相应缓存失效。收起的“先古/Boss”总览改为展开时生成。

长提示使用单个原生浮窗分页，悬停节点时按 **Shift+滚轮** 查看所有已计算内容。多组重掷和狩猎结果不再只展示前16条，上游选择变化不再只展示前8组；相同结果合并，重复的未变化牌组省略。分组时复用共享预测对象的完整结果键，保留升级、附魔与条件差异。

路线或内容计算截断时显示实际已计算数量，掉落与商品同步标为条件预测。空事件选项、未计算的战损说明和无数值的HP提示不再占行。具体参照选择仍显示，避免单一条件结果被读成所有选法都相同。

性能、原版对照与原生页面尺寸记录见 [再次体验排查](docs/validation/experience-audit-2026-10-14.md)。

## 0.1.30 复杂路线性能

奖励结算后打开地图时，收起的“战损与模拟”面板不再遍历全图或生成战斗候选；展开时才准备列表，相同跑局状态再次展开复用列表。路线搜索按目标可达性与剩余羽翼之靴次数剪枝，优先到达目标，只在找到完整路线时生成路径数组；达到路线预算仍注明截断。战斗候选提前排除需要经过其他战斗或未决事件的线路。

测量与路线完整性对照见 [复杂路线性能验证](docs/validation/route-performance-fixes-2026-10-14.md)。

## 0.1.29 变牌事件摘要

变牌事件按相同完整结果合并来源，每行最多显示两个来源牌名并保留实际张数，例如“打击、防御等12张牌变化为XX”。摘要使用卡名，避免卡图继续撑大浮窗；多次变牌按第几次分别显示，升级、附魔或结果列表不同的预测不会合并。底层每张来源牌的预测保持完整。

## 0.1.28 具体选择与内容变化

地图预测纳入当前尚未选择的事件初始页，包括开局涅奥；已选完的事件不会重复执行。当前事件先在独立跑局中按实际选项和选牌目标执行，再推进后方商店、战后掉落与宝箱。优先把当前选项推到目标，然后在剩余预算内枚举沿途选择。

提示用“参照选择”和“改为某选项”对应具体结果，仅列变化的格位、卡名、遗物、药水、升级、价格及金币。移除“选择会影响结果，请重算”“未覆盖”等没有具体替代内容的附加提示；浮木仍显示实际算出的各组选牌与重掷顺序。

原版对照和具体测试结果见 [具体选择变化验证](docs/validation/concrete-choice-diffs-2026-10-14.md)。

## 0.1.27 前置选择与浮木重掷

普通地图的远端商店增加前置选择条件：选牌、跳过、浮木重掷、拿取或跳过遗物，以及可无头执行的事件及其后续页，会在独立影子跑局中推进后再生成商店。不同条件下的相同库存合并显示；计算或展示达到上限、事件需要未覆盖操作时会明确注明，不把已计算结果当作全部可能。

普通战斗前瞻现在显示浮木重掷后的牌组，并区分“先重掷第 1 组再第 2 组”和相反顺序。转经轮与白星的额外组选牌沿用原生生成器；持有狩猎时，增加触发 0–3 次的条件预览。规划可指定狩猎触发次数，并按记录的跨组选牌、重掷、跳过顺序回放。普通重掷分支假设之前及期间没有领取奖励；规划仍先领取勾选的非卡牌奖励，再执行选牌序列。

宝箱、商店和挖掘得到的遗物改走原生领取流程，保留领取时的金币、随机升级、附加奖励及 RNG 变化。商店买牌保留完整卡牌状态并触发原生入牌效果。领取还需要未指定的选择时，规划会停止计算后续节点。

边界与验证见 [前置选择及重掷验证](docs/validation/upstream-choice-reroll-fixes-2026-10-14.md)。

## 0.1.26 预测准确性修正

普通地图的商店现在使用原版 `MerchantInventory.CreateForNormalMerchant`，保留半价牌第二次价格骰、上架去重、三种蛋的卡牌结果 Hook、会员卡与快递员折扣。生成只发生在影子跑局中，不把预测商品写进真实资料的发现记录。

远端事件在独立影子跑局中推进沿途楼层、历史与已见事件，修正楼层准入门槛；尚未执行的事件选择、购买、拿奖励和篝火动作仍属于条件。单结果和多结果视图都会注明这些条件及路线枚举截断；截断结果不会保留全路线“确定”标签。

战斗奖励明确显示为胜利后的基础掉落，并注明全歼、没有战中新增奖励或改写奖励状态的假设。商店库存、价格、卡牌升级和附魔状态参与路线分组。事件内容区分选牌目标映射、继续重抽序列、待选卡包和部分内容预览，并指出未覆盖的选项与后续页。

普通模式仍使用真实隐藏队列及 RNG 副本；战损对应求解器找到的打法。它没有接入只使用玩家可见信息的 blind 策略，找到终局路线也不代表最优或实战结果保证。

修复与验证记录见 [普通模式预测修复](docs/validation/non-plan-prediction-fixes-2026-10-14.md)。
## 当前兼容性

Seed Oracle `0.1.46` 适配游戏 `v0.113.0`：`SeedOracle.json` 的 `min_game_version` 设为 `0.113.0`，RitsuLib 门槛 `0.6.11`、Random Foreseer 门槛 `0.14.0`、Combat Solver 门槛 `0.51.3`；Mod loader 按 `min_version` 使用大于等于比较，因此后续主 Mod 版本无需跟随每次发布修改依赖。public API v5 是确定路线和当前状态假设样本的最低能力，规划战斗模拟会在运行时探测 v6 方法，旧的 v5 构建会安全降级为不可用。RitsuLib 需使用含 `compat/0.113.0` 的构建，Random Foreseer 需使用 `lib/0.14.0` 变体。详细核对记录见 [依赖兼容性审计](docs/validation/dependency-compatibility-2026-09-15.md)。

## 构建

复制 `local.props.example` 为 `local.props`，按本机路径调整后运行：

```powershell
dotnet build .\SeedOracle.csproj -c Release
```

`local.props` 中的 `CombatSolverDir` 应指向含所需 API 的 CombatSolver 构建目录；可以使用作者工坊条目 `2868840/3790899961`，或在审阅 v6 PR 时指向本地 Release 输出。不要把临时构建目录中的 SeedOracle 文件复制到 CombatSolver 目录。

默认会把 `SeedOracle.dll`、PDB 和清单部署到游戏目录的 `mods/SeedOracle`。

依赖：

- STS2-RitsuLib `0.6.11+`（需含 `compat/0.113.0`）
- Random Foreseer `0.14.0+`（`lib/0.14.0` 变体，适配游戏 0.113.0）
- Combat Solver `>=0.51.3`（public API v5 最低门槛；更新的主 Mod 版本自动兼容）；规划战斗模拟需 API v6 扩展

依赖能力审计见 [docs/capability-audit.md](docs/capability-audit.md)。

# 第一章牌组决策价值评估设计

这项工作要回答的问题是：在只使用正常流程能够获得的信息时，一张牌、一次商店购买或一次事件选择对后续通关结果的价值是多少。

Seed Oracle、Random Foreseer 和 Combat Solver 可以用来生成真实世界、验证转移和评估战斗，但训练中的决策者只能读取玩家当时合理知道的观察。不能把 Seed Oracle 的完整路线、未来事件内容、精确掉落或下一场敌人直接放进策略输入。

## 总体结构

系统分为四层：

1. **世界模拟器**：按照游戏原生 RNG、地图、遭遇、奖励、商店、事件和战斗规则推进一局，保留完整真实状态。
2. **信息过滤器**：从真实状态生成玩家观察，隐藏尚未进入问号、事件、商店和未来遭遇的具体结果，只保留正常流程中的规则、概率和已知历史。
3. **决策环境**：在可行动节点产生动作，例如选牌、跳过、购买、删牌、选事件选项、走哪条路、休息或强化。
4. **评估与学习器**：先运行随机、规则和有限深度搜索基线，再积累轨迹训练牌组价值模型和策略模型。

训练数据需要同时保存 `真实状态`、`玩家观察`、`动作`、`下一观察`、`奖励` 和 `终局结果`，但策略模型只能接收玩家观察。真实状态只用于推进环境、计算标签和离线审计。

## 第一章阶段和关键节点

第一版只处理第一章，并把决策压缩到以下阶段：

### 开局先古

输入角色、初始牌组、生命、遗物、难度和玩家可见的先古选项。先古选项本身可以作为观察输入；其后果由世界模拟器执行。模型需要学习的是选项对早期战斗、路线和精英可达性的长期影响，而不是直接读取后续路线结果。

### 路线与精英关键点

先生成地图上的所有可行路线，但策略输入只包含当前地图和已经知道的房间信息。第一章的路线搜索以精英为重要边界：

- 前三次普通战斗从弱怪池抽取；之后进入强怪池；
- 精英前三次出现时互不重复，后续按规则继续处理候选池；
- 精英不是唯一目标，小怪战损、火堆数量、商店可达性和 Boss 前状态仍作为评价项；
- 初版可以用“到下一个精英的生存概率 + 预期战损 + 预期成长”作为局部目标，减少完整三幕搜索规模。

牌局状态在每个战斗奖励后都会产生新分支。选牌动作包括每个合法卡牌选择和跳过，分支不能共享已经改变牌组、奖励 RNG 或药水状态的后续结果。

### 商店

商店购买视为一种带预算约束的奖励选择：购买卡牌、遗物、药水、删牌或离开。观察中不提供尚未进入商店时的精确库存和价格，只提供商店类型、当前金币、已知价格范围、购买槽位规则和可能的物品类别。进入商店后才把实际库存和价格作为观察。

### 路线剪枝

剪枝必须基于观察等价或状态等价，不能只按“当前看起来差不多”删除分支。

- **严格等价**：完整规划状态序列化后相同，且后续 RNG、地图历史和奖励袋相同，可以合并。
- **观察等价**：策略看到的观察相同，但真实状态不同，不能合并成一个确定分支；应保留为概率分布或抽样分支。
- **近似等价**：只在搜索预算不足时使用，并记录误差界，例如生命差不超过 1、牌组特征相同、同一精英边界；近似合并不能用于生成精确标签。

第一版建议使用 beam search：每个决策层保留固定数量的高分状态，并按 `生存概率、精英可达性、未来成长、金币、剩余路线选择` 排序。后续再加入基于状态哈希的 transposition table。

### 事件估值

事件动作必须使用进入事件前玩家能够知道的信息。未知事件的观察只有事件类型概率、房间位置、生命、金币、牌组摘要和已经访问过的事件历史；事件具体选项在进入后才揭示。

事件价值不应只用即时金币或生命变化评估，而应计算：

- 当前状态变化；
- 对下一精英和 Boss 的预期战损变化；
- 牌组污染、删牌机会和遗物协同；
- 对路线可达性、火堆和商店预算的影响；
- 事件后 RNG 和奖励袋变化造成的长期影响。

## 信息边界

训练环境必须明确区分三种信息：

| 信息 | 玩家在进入前是否知道 | 策略能否读取 |
| --- | --- | --- |
| 当前地图拓扑和已公开房间类型 | 是 | 是 |
| 第一章普通怪池、精英不重复等生成规则 | 是或可从规则推断 | 是 |
| 问号房间的累计概率权重 | 是 | 是 |
| 某个问号房间实际事件 | 否 | 否，进入后揭示 |
| 尚未进入商店的精确物品和价格 | 否 | 否 |
| 当前已进入商店的库存和价格 | 是 | 是 |
| 下一场尚未确定的具体怪物组 | 取决于游戏规则和已处理节点 | 只读取可知部分 |
| Seed Oracle 直接算出的完整未来掉落 | 否 | 否 |

Random Foreseer 的公平模式可以作为信息过滤器的参考，但不能直接把预测结果全部注入策略。建议每个观察字段带 `visibility` 和 `source`，训练前执行一次 forbidden-field 检查，防止未来信息从调试字段、缓存键或标签泄漏。

## 状态、动作和奖励

真实状态至少包含：

- 角色、生命、最大生命、牌组及升级/附魔；
- 遗物、药水、金币和删牌历史；
- 当前幕、楼层、地图历史、路线位置；
- 当前 RNG、遭遇队列、奖励袋、商店访问次数和事件历史；
- 当前战斗前后的奖励状态。

观察状态使用上述状态的可见投影，并额外提供规则允许的概率分布和不确定性标记。

动作分为：

- 选牌或跳过；
- 购买、删牌、离开商店；
- 休息、强化、其他火堆行为；
- 事件选项；
- 选择下一条地图边。

奖励建议先使用多目标形式保存，再在评估时加权：

```text
终局奖励
- 死亡惩罚
- Boss 胜利奖励
- 生命保留
- 牌组成长和关键能力完成度
- 金币、药水和遗物价值
- 路线长度与计算成本惩罚
```

不要一开始把所有目标压成单一分数。保留向量结果，方便比较“更容易打精英”和“更高终局上限”之间的取舍。

## 学习顺序

先不要直接训练端到端深度强化学习。建议分四步：

1. **规则基线**：随机选牌、永远跳过、优先攻击牌、优先精英生存、金币阈值商店策略。
2. **有限搜索**：在观察信息下做 1～3 个关键节点的 beam search，Combat Solver 提供战斗结果标签。
3. **监督价值模型**：用大量完整轨迹的终局结果训练 `V(observation, action)`，牌的价值先定义为选择该牌相对跳过的增量。
4. **策略改进**：用价值模型指导更宽的 beam search，再把新轨迹加入数据集，形成迭代改进。

每个牌的报告应至少包括：角色、先古选择、当前牌组、楼层、精英距离、金币、生命区间、候选动作、相对跳过的胜率变化、战损变化、置信区间和样本数量。不能只输出一个脱离上下文的“牌分数”。

## 第一阶段可交付物

第一阶段不做完整学习模型，先实现可验证的离线环境：

1. 从固定种子生成第一章真实世界轨迹；
2. 生成遵守信息边界的玩家观察；
3. 支持先古、路线、战斗奖励、商店、火堆和事件动作；
4. 接入 Combat Solver 计算精英和 Boss 战斗标签；

### 战斗样本去重

路线分支不等于战斗分支。第一章的多条路线可能在不同地图坐标进入同一个首战序列，因此应先按公平可知的序列状态分组，再提交 Combat Solver。分组键包括玩家状态快照、层数、房间类型、此前经过的普通战/精英/事件/商店计数和前置房间状态；不能只按“结果相同”合并，也不应把玩家不可能知道的完整怪物随机流泄漏给策略。当前原型把 81 条路线压缩成 1 个首战请求，同时记录本体战斗随机流探针（该种子仍有 3 个坐标值）作为审计字段。

本体的 `ActModel.GenerateRooms` 预先生成并保存多条独立序列：事件列表先洗牌；普通战斗先生成固定数量的弱怪池，再生成普通池；精英单独生成 15 个位置，并在抓取池耗尽前避免重复标签；Boss 单独抽取。`RoomSet` 只在实际进入对应房间时推进对应计数，商店不推进战斗序列，而是消耗玩家的 `Shops` RNG 和遗物抓取袋。问号房间另有 `UnknownMapPoint` RNG、累计权重和“上一房间是商店”等限制，解析结果会改变后续对应序列的推进。事件还会检查 `IsAllowed`、已访问事件和 mod hook，因此“同一事件序号”只有在这些条件和玩家资源状态等价时才可合并。
5. 用状态哈希合并严格等价节点，用 beam width 控制近似搜索；
6. 输出 JSONL/Parquet 轨迹和 forbidden-field 审计报告；
7. 用随机策略和几个规则策略跑基线，确认观察中没有未来信息。

这个离线环境应作为独立项目或独立工具运行，SeedOracle 只提供适配器和验证数据，不在游戏主进程里执行大规模训练。

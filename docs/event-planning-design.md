# 事件规划：从单一选项到可继续的条件世界线

事件规划不能把“点了哪一个初始按钮”当成完整决策。很多事件还有第二页、卡牌网格、奖励拿取、
特殊战斗或小游戏；只有这些条件都确定以后，后续商店、奖励、牌组和战损预测才有一条可精确推进的
世界线。

## 当前基础（0.1.22）

- 下拉框以游戏实际生成的 `CurrentOptions` 为唯一索引来源。规划链直接克隆当前跑局并调用游戏原生
  生成逻辑，不读取 Random Foreseer 的事件预测注册表；没有随机内容的离开、过渡或保底选项不会再
  被漏掉，也不会造成后续选项错位。
- 锁定选项不能选择。每个可见选项在下拉框中标出处理方式：`✓` 精确、`◇` 奖励待选、`◆` 卡牌/
  交互待选、`⚔` 特殊战斗、`▦` 小游戏、`✕` 终止跑局。
- 特殊战斗只计算“若获胜”的掉落，不启动房间或战斗场景；水晶球继续使用专用 11×11 布局。
- 改动当前或上游计划选择时，清除本节点及下游已经计算的事件结果。异步结果回来时再次核对当前
  选项，避免把旧世界线结果写进新计划。
- 删除、强化、转化、附魔等牌组内选择会显示当前规划牌组；脑蛭“分享知识”会按同一影子状态生成
  5 张候选并要求选择 1 张。完成选择和预演后，结果中的牌组、药水与随机数状态会接入后续路线。
- `Trial(REJECT)` 和 `WarHistorianRepy(UNLOCK_CAGE)` 已从过宽的降级匹配中释放；真正需要界面的
  `DOUBLE_DOWN`、`UNLOCK_CHEST` 仍单独分类。

当前实现不会把待选奖励误算成已经拿到，也不会在后台打开奖励或小游戏界面。尚未实现的奖励拿取
与多页交互仍会阻断后续台账，直到规划模式能够明确记录这些决定。

## 完整事件计划的数据模型

下一步把 `RoutePlanChoice.EventOption` 扩展为一条按 `TextKey` 保存的步骤链，而不是只保存初始
数组下标：

1. 初始选项与每一页后续选项；
2. 每次卡牌选择的卡牌实例（模型 ID 加同名牌序号，支持一次选多张）；
3. 每组奖励的拿取、跳过、卡牌选择和药水替换；
4. 特殊战斗的“进入/离开、假定胜利、预计战损与用药”；
5. 小游戏实际准备取得的格子/物品；
6. 终止跑局标记。

数组下标只在当次生成的页面内使用。持久的计划用 `TextKey`，这样状态变化导致某个锁定选项增减时，
不会悄悄改成另一个选择。

## 执行方式

事件执行器应返回两种结果之一：`Completed` 或 `PendingDecision`。遇到原生 UI 边界时不打开界面，
而是暂停同一份影子事件并把待选内容交给规划面板：

- `RewardsCmd.OfferCustom`：只生成并应用奖励 Hook，返回卡牌、遗物、药水和金币候选；用户选择后在
  影子状态上结算，再继续事件闭包。
- `CardSelectCmd`：按计划提供多次、多张卡牌选择；不再默认取第一张。
- 多页事件：每执行一步都读取新的 `CurrentOptions`，显示下一页并在同一影子状态上继续。
- `BattlewornDummy`、`PunchOff`、`DenseVegetation(FIGHT)`：先形成特殊遭遇描述。现有作者工坊版
  Combat Solver API 能覆盖时直接估算；若接口不能表达某类事件遭遇，先在 Seed Oracle 做专用适配，
  只有确实需要改公共 API 时才考虑更新上游 PR。
- `CrystalSphere`：布局预测之后记录玩家准备获取的物品，而不是假定拿完所有物品。
- `Amalgamator`：把等待动画帧的部分改写成模型级待选步骤，不等待 Godot UI 信号。
- `Trial(DOUBLE_DOWN)` 等终止选择：立即截断后续世界线。

事件完成后，规划链应接管整份影子状态，而不只叠加显示用的金币/HP 差值。需要继续传递的内容包括
牌组、遗物、药水槽、金币、HP、事件/跑局标志、Rewards RNG、卡牌稀有度赔率和双遗物袋。这样事件
拿走一个遗物后，下游商店和精英掉落才会自然改变。

## 不完整条件的显示

只要存在未回答的 `PendingDecision`，该节点之后就不再标“精确”。界面可以选择一种明确行为：

- 用户补齐选择后继续单一世界线；
- 对少量候选建立并排分支；
- 特殊战斗只给出胜/败或战损区间，后续标成条件结果。

缓存键应包含跑局状态令牌、路线前缀、事件 ID、步骤 `TextKey` 链和全部附加选择。相同状态再次打开
面板可直接复用；改变上游选择时只失效受影响的后缀。

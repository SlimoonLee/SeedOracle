# 事件规划与药水状态

路线规划从独立跑局快照出发，调用游戏原生事件选项与选牌流程。每一步完成后，牌组、药水槽、金币、生命、遗物、历史记录与随机数状态一起接入后续节点。

## 状态与选择

- 药水只保存在影子玩家的原生 `PotionSlots` 中。节点面板从该节点的 `StatesBefore` 还原玩家，终点台账读取链末玩家，不维护第二份可变药水清单。
- 未指定药水选择时按空槽拾取；空的显式选择表示跳过。满槽时只有明确指定丢弃对象才替换；未知药水 ID 不会先删掉已有药水。
- `RunState.FromSerializable` 会复用输入中的部分历史对象。进入规划/事件执行前，使用游戏的 `JsonSerializationUtility` 做完整序列化往返，避免执行影响真实跑局或修改已缓存快照。
- `ShadowIsolation` 使用复制后修改的异步上下文栈；原生选牌器和非交互状态只在影子执行中覆盖，不写入游戏全局选牌栈。

## 通用事件处理

选项索引来自本页原生 `CurrentOptions`。探测器执行隔离副本，记录 `ICardSelector` 收到的每次请求，包括候选卡、牌组槽位、最小/最大选择数量和步骤顺序。后续请求会按用户已选择的前序卡牌重新生成。已删除按事件名称手工生成候选的规则表。

卡牌奖励通过独立的 `RewardsSet.Offer` / `CardReward.OnSelect` 边界处理：保留原生奖励生成、奖励 Hook、重复选牌、获得卡牌与历史记录，省去真实奖励界面与多人同步。脑蛭分享知识的五选一、撕扯的三选一，以及多彩哲学家的三组奖励使用同一条流程。

合成器是一个明确的兼容特例：游戏动作包含无条件动画等待。影子执行保留原生两张基础打击/防御的过滤、删牌和获得究极牌命令，省略动画和音频。

普通事件奖励可明确选择领取或跳过。领取时按原生槽位容量处理药水，满槽的额外药水记为跳过；当前不提供事件奖励的逐瓶替换或任意子集选择。

多页事件把已完成步骤保存为 `TextKey + 卡牌选择 + 奖励策略`。面板提供“选择后续事件选项”和“从事件起点重选”。每次重新预演都从节点入口快照回放这条路径；无法匹配的旧步骤、失效的牌组槽位和变更的选项会拒绝执行。只有整个事件完成后才推进后续规划链。

## 已执行验证

### 战斗奖励分组

战斗奖励以原生 `RewardsSet` 中的 `CardReward` 实例为组边界。每组分别记录选择步骤；候选扩展、额外奖励组与替代选项分别来自 `CardCreationOptions`、奖励 Hook 和 `CardRewardAlternative.Generate`，不按遗物名称推断语义。

- 转经轮和白星保留独立的额外组，白星额外组沿用原生首领稀有度。
- 吃不完的糖由原生 `IsFromCombat` 等生成标记判断作用范围，与转经轮同时持有时，触发战斗显示 4+3，而不是一组六选一或两组四选一。
- 献祭、跳过和重抽执行原生替代选项；重抽后在同组追加选牌步骤。改动前序选择会清除该组之后的步骤，其他组仍保留。
- 领取使用原生奖励命令，献祭计数、遗物获得、卡牌变化、奖励历史与 RNG 接入后续快照；过期卡牌索引或 ID 被拒绝。需要额外牌组目标的奖励明确报出未支持的选择，不擅自选牌。
- 地图战斗、宝箱和事件内容预览的前置战斗统一走同一原生路径，已移除旧的遗物奖励分支表。奖励对象的遗物监听器在预览和执行结束后释放。

隔离无头审计通过：两组分别拿牌、一组跳过、失效选择、白星稀有度、糖与转经轮 4+3、跨战斗/同战斗两次献祭、重抽后选牌、快照与 RNG 重放，以及地图/规划入口一致性。烟雾脚本同时要求奖励分组 PASS、事件零失败摘要和游戏进程正常退出。

随后在隔离主进程中跑了多轮不同种子：两轮完整 AutoSlay 从开局走到胜利并经过战斗奖励、商店、宝箱、休息点和事件；另两轮分别覆盖快速规划审计与完整 Debug 自检。完整 Debug 自检报告 `map_types=8`、`route_variants=135`、商店 13 项、战斗奖励和宝箱均通过；四轮均无规划污染、奖励界面卡住或异常退出。

2026-09-07，通过 `smoke/run-planning-smoke.ps1` 在独立游戏目录、独立 APPDATA/LOCALAPPDATA 和关闭 Steam 的无头进程中验证。测试构建启用 Debug 纯净性检查，读取现有进度作为测试模板，不向真实存档目录回写。

- 枚举 57 个非先古事件、119 个初始选项；100 个选项成功重复执行，完整跑局状态指纹一致，未发现真实跑局污染。
- 其余 21 项包括 12 个在测试状态中锁定的选项、7 个特殊战斗/水晶球选项，以及 2 个没有普通初始选项的事件（FakeMerchant、TheFutureOfPotions）。不能据此宣称所有特殊交互均已支持。
- 脑蛭两个分支分别验证了首张与末张候选；缺少选牌和失效选项被拒绝。
- 审判与修补时间分别验证了 4 条完整终点路径；验证多页回放及后续选牌。
- 8 个普通奖励选项分别验证领取和跳过。
- 药水验证覆盖爆炸安瓿/肌肉药水的快照往返、默认拾取、显式跳过、满槽拒绝、替换、重复索引和早期快照不变。

完整输出见 [规划审计记录](validation/planning-audit-2026-09-07.txt)。这是指定种子与测试状态下的可重复证据；实际游戏面板的鼠标操作和用户当前跑局仍需实机复核。

## 规划战斗模拟

普通、精英、首领和问号点解析出的战斗从该节点的 `StatesBefore` 发起；事件选项先在该节点快照上执行前序页面、选牌和生命变化，捕获原生 `EventCombatSynchronizer.ReadyToEnterCombat` 后再发起模拟。每批默认 3 次，可选 1～10 次。每个请求从游戏主线程捕获状态，在独立 CombatSolver worker 中加载规划存档；真实跑局只用于环境捕获和完成后的状态校验。

调用使用本地扩展的 CombatSolver API v6。遭遇解析读取模型注册表 `ModelDb.All`，而不是并不完整的 `AllEncounters` 列表；茂密植被等遗漏事件因此无需名称补丁。原有使用实际状态的模拟面板也增加了指定事件战斗入口。规划快照保留独立地图、地图点可修改标记、牌组、药水、HP、遗物、历史与 RNG，序列化往返不重新生成地图。

只允许已完成且玩家存活的成功样本写入参照。参照绑定节点坐标、遭遇、房间类型和入口状态指纹，保存样本 seed、最终 HP 和实际用药槽位。后续规划直接采用样本最终 HP，再执行原生战后 Hook 与奖励；累计受伤量不等于净 HP 变化，不能用它再次扣血或覆盖战斗内治疗。前序计划改变后，过期参照会阻断后续节点并要求重新模拟。

事件战后额外奖励、原生 `Resume` 和后续页面接入同一规划链，卡牌组、药水和遗物沿用战斗奖励取舍控件。事件探测通过原生战斗边界识别，支持先选牌再进入战斗；没有按事件名称判断战斗的规则表。

本轮可重复后台证据见 [规划战斗验证](validation/planning-combat-2026-09-08.md)。这验证指定状态的模拟与参照回放，不等同于未来实际战斗必然得到同一结果。

## 现有边界

水晶球使用专用布局预测，不自动领取全部小游戏物品。FakeMerchant 和 TheFutureOfPotions 的定制界面尚未纳入通用事件步骤。失败或未完成的战斗样本不能作为规划参照；尚未完成的事件会阻断后续规划状态，并在面板中说明原因。模拟参照目前传递最终 HP 和用药，不是整场战斗所有永久卡牌、遗物内部状态变化的完整回放。

# 0.1.31 再次体验排查

## 排查结果

| 问题 | 修复 |
| --- | --- |
| 0.1.30只优化了路线搜索，完整远端悬停仍重复恢复跑局、生成相同库存 | 已知固定房间直接推进队列计数；相同基础序列复用；同状态悬停缓存最多12个节点 |
| 原生事件/问号线路和上游选择仍可能占用主线程过久 | 房间推演75 ms、具体内容250 ms、上游选择150 ms的分阶段预算；在原生操作之间检查，未算完保留条件与数量 |
| 512条路线反复复制包含64种多组奖励的完整分组键 | 先按共享预测引用归组，再用完整内容键合并；不牺牲升级、附魔或条件信息 |
| 收起的先古/Boss总览每次开地图重算 | 绑定时不计算；展开时生成，同状态复用 |
| 只展示前16种重掷、前8组上游变化及前8类路线结果 | 全部已算结果保留，通过Shift+滚轮翻页查看；相同结果合并，未变化组选牌不重复显示 |
| 路线截断时总览降级，但部分逐路线商品/掉落仍显示当前世界线确定 | 同步降为条件预测；具体参照条件即使只有一组结果也显示 |
| 开启卡图或长中文时，浮窗调整位置仍无法解决超高 | 单个原生面板分页，限制行宽、文字行数及卡图行占用；翻页复用同一控件 |
| 没有数值的HP、未计算战损、空事件选项占据多行 | 移除这些行，事件重抽的相同结果按次数合并 |
| 文字模式可能省略升级/附魔状态 | 卡名统一追加升级和附魔名称/量，具体差异共用此格式 |

上述时间预算为原生操作间的检查点，不是在操作中强行中断；单次原生Hook的耗时仍可能超过预算。预测仍只覆盖已实现的机制和已算分支，未将降级的事件改称完整精确预测。

## 实测

环境：复制游戏和玩家资料的无头游戏，原版0.111.0、种子 `ROUTE_PERF_20261014`。512路线商店用4列合流地图、前置5个休息房和羽翼之靴剩余3次，调用完整 `MapForecastService.Predict`，非仅测路线搜索。分配字节是本线程累计分配量，并非常驻内存。

| 指标 | 0.1.30基线 | 0.1.31 |
| --- | --- | --- |
| 完整商店悬停预测 | 1286 ms | 188 ms |
| 预测累计分配 | 999060096 B | 86059296 B |
| 同状态再次预测 | 重算 | 缓存命中，<1 ms |
| 浮窗内容构建 | 11 ms | <1 ms |
| 同一基础库存生成 | 每条坐标路线 | 1次 |

多组压力测试：512条共享预测路线、64种可能结果、每结果3组选牌、每组3张带原生序列化状态的牌。分组2 ms，累计分配4106912 B；与不同价格、升级、附魔的独立分组回归同时通过。

## 验证与边界

- 106个原生场景面板测量：720p/1080p、长中文、40种具体重掷结果、80组变化、重复卡图。所有页面高度小于视口减24像素；分页前后可见字符完整保留。
- Shift+滚轮处理路径通过，翻页后原生浮窗实例相同，无重新预测。未实测玩家设备上的鼠标事件传递或截图效果。
- 40个合成重掷结果均可读取，包括狩猎3次；计算达到上限时显示实际已算数量。合成数据验证显示覆盖，原生有序重掷26例验证卡牌与RNG内容。
- 卡牌领取及羽翼之靴次数变化使悬停缓存失效；20次收起的总览绑定不生成预测；收起的战损面板仍无候选计算。
- 4条固定房间线路与完整影子跑局推进一致；共享库存与原版生成器结果一致。原版商店12例、55个路线对照、涅奥3选项及前置选择、事件后续页、药水和规划模拟通过。
- 最终事件审计：106支持、15降级、0不确定、0失败。跑局/RNG和玩家资料纯度回归通过。
- 未测量主游戏帧时间、显卡占用或长期内存曲线。首轮悬停仍有约188 ms同步工作，不能据此承诺任意Mod组合和地图均无停顿。

原始证据：`.local/experience-audit-20261014/baseline-report.txt`、`smoke-report.txt`、`baseline-godot.log`、`godot.log`。构建、安装与压缩包哈希记录为同目录 `deployment.json`。

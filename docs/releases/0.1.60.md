# Seed Oracle 0.1.60

0.1.59 上传后两天的实测修复轮：全部由玩家实测反馈 + `[BlitzAudit]` 购买审计 + 全类型 parity 夹具驱动定位。极速商店的预测与真实购买现已逐字一致（20 类条目全 OK）。

## 修复

1. **奖励选牌即时重算**：从奖励界面把牌拿进牌库不经过商店条目，此前窗口按进场时的牌库给变化/自动升级/附魔行报价。现在挂 `Hook.AfterCardChangedPiles` 通知重算，指纹含牌库摘要。
2. **四处直生偏差（"添柴+变披风"的根源）**：
   - 升级稀有卡漏传 `WithRngOverride(shops)`——抽取静默走到 Rewards 流，自身内容错且 Shops 消耗记成 0，同架后续货物位置漂移 1；
   - 升级卡牌奖励是 1 屏不是 2 屏（多抽 9 次，后续位置漂移 9）；
   - 随机升级应"先过滤可升级牌再洗牌"（原实现诅咒参与洗牌，同种子落在不同牌上）；
   - 升级名显示未加"+"、删牌可选数未排除不可移除牌（Eternal）。
   自检新增**全类型 parity 夹具**：20 类条目全部与真实购买探针逐字对照，作为常驻门禁。
3. **变化愿望绑定来源**：变化结果取决于来源牌的池子（角色/诅咒/无色各不相同）。变化结果 chip 携带产生它的全部来源，愿望一并绑定；解算器只放行"来源可作为候选"的顺序，计划行写明"（选 X 去变化）"。
4. **变化表覆盖奖励牌与诅咒**：先买卡牌奖励拿到的牌、诅咒货物送进牌库的诅咒都可变化，并列出每个结果的全部获取路径（牌库／奖励屏／诅咒）。
5. **[BlitzAudit] 购买审计**：每次真实买下货物，godot.log 输出一行"窗口承诺 vs 实际进牌库"判定，区分屏内选牌与真意外；变化购买核对"实际移除的源 → 落地牌"与行内承诺。
6. **窗口可用性**：收起改为折叠成标题条留在原地（不再依赖外部按钮）；悬浮信息卡按游戏 mega_text 层要求携带主题字体覆盖（此前每次悬浮抛异常）；悬浮卡挂独立 CanvasLayer 不再参与容器布局（修复闪烁与卡死）；窗口布局后自动夹回可视视口。
7. **线程与部署**：枚举全程主线程逐帧分片（影子购买可触及游戏 UI 副作用，后台线程曾导致卡死）；进店零同步成本、购买后防抖重算、前缀签名去重。
8. **遗留路径**：RF 适配器旧商店预测的遗物稀有度误用 Rewards 流（游戏用 Shops），已修正（该路径现仅测试使用，生产预测走原生生成器）。

自检门禁 57 项全 PASS，含 20 类直生/真实购买逐字 parity 与四层牌库摘要一致性。
